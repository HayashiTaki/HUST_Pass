# 华中科技大学统一身份认证系统自动登录助手

**在 Microsoft Edge（或其他使用Chromium内核的浏览器） 中，自动完成“智慧华中大统一身份认证系统”的登录。**

适用页面：[https://pass.hust.edu.cn/cas/login](https://pass.hust.edu.cn/cas/login)  
当前扩展版本：**0.1.3**

请注意：这是一个安装在浏览器中的小工具，安装后不需要单独打开一个应用。如果您想体验完全的自动登录，需要使用浏览器的密码管理器自动填写登录学号和密码，本扩展负责本地识别动图验证码和确认登录这两个步骤。

如果你已经拿到打包好的安装文件，**不需要会编程，也不需要安装 Node.js、Python 或 Git**。直接阅读下面的安装和使用部分即可。

## 这个扩展能做什么

华中大的统一认证密码登录页通常需要三项内容：人员编号／学号、密码、验证码。验证码是一张四位数字的动图，数字会轮流闪烁。

正常使用时，整个过程如下：

1. 你从课程平台等业务系统进入统一认证页，或者直接打开上面的认证地址。
2. Edge 的密码管理器自动填好学号和密码（如果没有保存过账号，也可以由你填写）。
3. 扩展识别验证码动图，将识别出的四位数字写入验证码输入框。
4. 扩展点击页面原有的“登录”按钮。
5. 学校认证系统检查登录信息，并按网站原有流程完成登录或显示错误。

| 操作 | 由谁负责 |
| --- | --- |
| 提供学号和密码 |  Edge 密码管理器 |
| 识别并填写验证码 | 本扩展，在本机完成 |
| 点击原网页的登录按钮 | 本扩展；你也可以手动提交 |
| 判断账号密码是否正确、完成身份认证 | 学校认证系统 |
| 登录后返回业务平台 | 网站原有跳转流程 |

扩展支持登录地址后附带 `service` 等跳转参数的情况。**从业务平台跳转过来时，保留原来的完整地址即可，不需要删除问号后面的内容。**

它不提供学校账号、不找回或修改密码、不代替扫码登录，也不会替你完成短信验证码等额外认证。它只处理上述统一认证页中的密码登录，不会在其他网站自动填写验证码。

## 开始前需要准备什么

- **Microsoft Edge 浏览器。** 其他使用Chromium内核并有密码管理器的浏览器理论上也可，当前开发和测试环境为 Windows 上的 Edge；其他浏览器或操作系统未做同等验证。
- **能正常访问学校认证页的网络。** 识别在本机进行，但访问网页和登录学校系统仍然需要网络。
- **有效的学号／人员编号和密码。** 扩展不会帮你获取这些信息。
- **扩展安装文件。** 先确认自己拿到的是下面哪一种文件。

| 你拿到的内容 | 下一步 |
| --- | --- |
| `hust-pass-assistant-v0.1.3.zip` 这样的已构建安装包 | 按“方式一”解压并加载 |
| 已经生成的 `dist` 文件夹 | 按“方式二”直接加载 |
| 包含 `package.json`、`src`、`public` 等内容的源码目录或源码 ZIP | 先按文末开发说明构建，生成 `dist` 后再加载 |

本项目当前采用本地加载方式安装，不需要从扩展商店搜索。普通用户使用已构建安装包即可。

## 安装到 Microsoft Edge

### 方式一：使用 ZIP 安装包

1. 将安装包保存到一个打算长期保留的位置。
2. 在文件资源管理器中右键 ZIP，选择“全部解压缩”，或使用你熟悉的解压工具。**不要只在压缩包预览窗口中打开文件。**
3. 打开解压后的文件夹，找到直接包含 `manifest.json` 的那一层目录。正确结构大致如下：

   ```text
   hust-pass-assistant-v0.1.3/
   ├── manifest.json
   ├── background.js
   ├── content.js
   ├── popup.html
   ├── offscreen.html
   ├── vendor/
   ├── README.md
   └── ...
   ```

4. 打开 Edge，在**浏览器地址栏**输入 `edge://extensions`，按 Enter。不是在搜索引擎的搜索框中输入。
5. 在扩展管理页面中打开“开发人员模式”。这是扩展管理页上的开关，**不是按 F12 打开的开发者工具**。
6. 点击“加载解压缩的扩展”，选择第 3 步找到的文件夹，再点击“选择文件夹”。要选择整个文件夹，而不是 ZIP 或 `manifest.json` 文件。
7. 在扩展列表中确认出现“华中大验证码助手”，处于启用状态，版本为 **0.1.3**。如浏览器要求确认权限，请先阅读本文的权限说明，再决定是否启用。
8. 如果认证页已经打开，刷新一次该页面，让新安装的扩展开始工作。

加载后，请保留解压目录。Edge 会从这个目录读取扩展文件；不要将它当作一次性的安装缓存删除或移动。

### 方式二：使用已有的 dist 文件夹

如果你拿到的是完整项目，而且里面已经有 `dist` 文件夹，按方式一的第 4～8 步操作，在选择目录时选中 `dist` 即可。

```text
项目根目录/
├── package.json
├── src/
├── public/
└── dist/                  ← 在 Edge 中选择这一层
    ├── manifest.json
    ├── content.js
    └── ...
```

**不要选择项目根目录，也不要选择 `public`。** `public` 虽然有一份 `manifest.json`，但不是完整的可安装产物，缺少构建生成的脚本和本地识别资源。

如需对照浏览器的官方说明，可参考 [Microsoft Edge：本地加载、更新和移除扩展](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)。

### 如何打开扩展控制面板

点击 Edge 地址栏右侧的“扩展”菜单，找到“华中大验证码助手”并点击，就能打开控制面板。也可以在该菜单中将它显示在工具栏，方便以后开关和查看状态。

找不到工具栏图标时，先到 `edge://extensions` 确认扩展已经安装并启用；工具栏没有图标不一定表示安装失败。

## 第一次使用与日常登录

### 推荐的登录步骤

1. 打开需要访问的学校业务平台，沿用它提供的登录入口进入统一认证页。也可以直接打开 [统一认证页](https://pass.hust.edu.cn/cas/login)。
2. 确认页面显示的是**密码登录**区域，并且能看到学号、密码、验证码和登录按钮。
3. 等待 Edge 填入账号密码。如果浏览器没有保存账号，可以先手动填写一次再保存到密码管理器。浏览器若要求选择一个已保存账号或解锁密码管理器，先完成它自己的提示。
4. 保持该登录标签页在前台，稍等扩展处理。通常不需要点击验证码框，也不需要自己点击登录。
5. 查看网站是否成功跳转。若网站显示密码错误或额外认证要求，按网站提示处理。

扩展默认开启“自动填写并登录”。学号和密码就绪并稳定约 **310 毫秒**后会开始处理；这不是“310 毫秒内完成登录”的承诺，实际还需要加载验证码、初始化识别引擎和等待网络响应。

首次识别可能比后续识别慢。**“已点击登录，等待网站响应”只表示扩展已经按下登录按钮，不表示学校已经确认登录成功。**

### 为什么有时会自动点击一下验证码框

Edge 有时已经把账号密码显示在页面上，但暂时还没有把实际值提供给网页脚本，直到页面发生一次交互才完成填充。

遇到这种状态，扩展会在当前登录页短暂使用浏览器调试功能，自动点击一次验证码输入框，然后断开连接。这个动作是为了让浏览器完成填充，不需要你手动补点一次。

每个页面文档最多尝试激活一次。如果提示激活超时、被取消或浏览器仍未提供填充值，先检查页面和浏览器提示，再刷新登录页。单纯点击“重新尝试”不会让同一个页面反复执行激活动作。

### 如果只想手动登录

先在扩展控制面板中关闭“自动填写并登录”，再自行填写验证码、点击登录。这样可以明确暂停自动流程。

即使没有先关开关，只要你开始手动填写验证码，或手动点击登录／按 Enter 提交，扩展也会停止当前自动任务，避免覆盖你的验证码或再次提交。

## 开关、状态与重新尝试

控制面板提供三个主要信息：

| 控件或信息 | 含义与用法 |
| --- | --- |
| 自动填写并登录 | 总开关。关闭后暂停自动处理；重新开启后，在当前登录页点击“重新尝试”启动新一轮 |
| 当前状态 | 显示正在等待、识别、提交，或已经停止的原因。登录按钮附近也会显示处理提示，措辞可能稍有不同 |
| 本轮已尝试 X / 3 次 | 当前一轮的验证码尝试计数，不是历史登录总次数 |
| 重新尝试 | 明确启动新一轮自动处理，并重新计算这一轮的尝试次数 |

“重新尝试”在非支持页面、扩展关闭或任务仍在激活／识别／提交时可能不可用。先查看状态，不需要反复点击。

### 看到这些状态时应该做什么

| 常见状态或类似提示 | 说明 | 建议操作 |
| --- | --- | --- |
| 等待浏览器填好学号和密码 | 字段尚未就绪 | 检查是否已选择账号、填写密码，并保持密码登录区域可见 |
| 正在确认浏览器自动填充 | 正在激活浏览器已显示的填充内容 | 稍等；若失败，按提示检查权限并刷新页面 |
| 等待账号密码稳定后继续 | 刚刚修改了账号密码，或旧任务因修改而被丢弃 | 完成输入后稍等，会自动继续，无需点击重试 |
| 正在本地识别 | 正在处理验证码动图 | 稍等，保持标签页在前台 |
| 识别不确定，准备刷新验证码 | 当前结果不能可靠使用 | 扩展会在次数上限内换图重试 |
| 已点击登录，等待网站响应 | 已交给网站处理 | 等待跳转；最终以网站结果为准 |
| 已尝试 3 次 | 本轮自动尝试用尽 | 手动填写，或检查原因后点击“重新尝试” |
| 已切换为手动填写／已有手动验证码 | 检测到了你自己填写的验证码 | 手动完成登录；若想改回自动识别，先清空手动验证码，再点击“重新尝试” |
| 另一个登录页正在处理／已加载 | 多个认证页面发生了冲突 | 留下需要使用的那个认证页，返回前台，再按提示重新尝试或刷新 |
| 需要额外认证 | 网站要求短信等进一步验证 | 按网站要求由你本人完成 |
| 验证码助手已暂停 | 总开关关闭 | 需要自动处理时开启开关，并点击“重新尝试” |

### 重试次数如何计算

一轮最多处理 **3 次：首次尝试，加最多 2 次自动重试**。只有识别结果不够确定，或网站明确报告验证码错误时，才会在剩余次数内自动重试。

账号密码错误、未知网站错误、网络失败或额外认证不会触发反复登录。自动填充激活不占用验证码尝试次数；因账号密码编辑而丢弃的当前未提交任务，也不会清零之前已发生的验证码失败次数。

刷新页面与“重新尝试”不是同一件事：刷新用于重新加载页面或恢复激活流程，**不保证清除已有的重试限制**；确认问题已处理后，“重新尝试”才是显式开启新一轮的入口。

## 哪些操作会继续，哪些会停止

0.1.3 已移除普通鼠标、键盘操作触发的自动中止逻辑，不再通过匹配鼠标事件来猜测是否需要停止。

| 你的操作或页面变化 | 扩展行为 |
| --- | --- |
| 普通点击、重复点击验证码框、普通按键 | 不会仅因为这些操作而中止自动登录 |
| 修改学号或密码 | 等待输入稳定后自动继续；必要时释放旧识别任务，重新处理 |
| 手动输入验证码 | 停止当前自动任务，保留你的输入 |
| 点击登录按钮，或在登录输入框按 Enter 提交 | 交由网站处理，不再重复提交 |
| 点击验证码图片刷新 | 旧验证码任务停止；想交回自动处理时点击“重新尝试” |
| 切换扫码／密码登录方式 | 停止原来的密码登录任务 |
| 识别或激活期间切换到其他标签页 | 当前任务停止；返回后按提示恢复 |
| 离开认证页、刷新页面、验证码被替换 | 旧任务不会把识别结果写入新页面或新验证码 |
| 关闭扩展开关 | 暂停自动处理 |

不要同时让多个学校认证标签页处理同一登录过程。它们可能共享学校的会话和验证码状态；在另一页刷新验证码，可能使当前页的验证码失效。扩展会协调自身任务，但无法协调其他浏览器配置或未运行此扩展的页面。

## 常见问题与排查

### 1. Edge 提示无法加载扩展，或找不到 manifest.json

检查是否已经完整解压，以及选中的文件夹内是否**直接**包含 `manifest.json`。如果里面还套了一层同名目录，进入下一层再选择。

如果只看到 `package.json`、`src`、`public`，你拿到的是源码。先构建出 `dist`，或向提供者获取已构建安装包。不要单独拿 `public/manifest.json` 安装。

### 2. 账号密码已经显示，为什么还是等待

先确认运行的是 **0.1.3**，并且更新后做了两件事：在扩展管理页重新加载扩展、刷新原来的登录网页。

然后检查密码登录区域是否可见，是否需要先选择保存的账号或解锁密码管理器。当前版本会尝试自动激活已显示的填充内容；如果状态明确报告激活失败，请处理该错误并刷新，而不是一直等待。

### 3. 出现“正在调试此浏览器”之类的提示，正常吗

这是自动填充激活步骤使用 `debugger` 权限时可能出现的浏览器提示。扩展只在需要时连接当前认证页，点击完成后立即断开；账号密码已经就绪时不需要连接。

如果取消调试连接，本次激活可能失败。若不希望使用这项能力，可以暂停或移除扩展，改为手动登录。

### 4. 提示无法激活自动填充或无法连接调试器

检查扩展是否已启用、新增权限是否已确认，以及当前登录页是否开着 F12 开发者工具。关闭该页开发者工具后刷新再试。

部分受管理的浏览器可能限制调试连接。此时按浏览器或组织的管理要求处理，扩展本身不能解除限制。

### 5. 仍看到“你正在操作登录页”或“检测到额外鼠标操作”的旧提示

这些通用中止提示对应的逻辑已在 0.1.3 删除。请依次检查：

1. 扩展列表中显示的版本是否为 0.1.3。
2. 是否仍有另一份旧版本扩展处于启用状态。
3. 重新加载扩展之后，是否也刷新了原来的登录页。
4. 加载的目录是否真的是新版本目录，而不是旧的解压目录。

### 6. 验证码识别失败，或者已经尝试三次

扩展不会对不确定的结果强行提交。可以手动填写本次验证码，也可以检查网络与页面后启动新一轮。

如果学校更换了验证码样式，旧版识别方式可能不再适用。反馈时提供版本号、状态提示和发生步骤即可，不需要提供账号密码。

### 7. 填好验证码后没有登录成功

先看学校网页自己的提示。可能是账号密码错误、需要额外认证、网络请求未完成，或网站没有按预期返回。扩展按下登录按钮并不等于登录成功。

扩展不会修改密码，也不会遇到账号密码错误后持续重试。先处理页面报告的问题，再决定是否重新尝试。

### 8. 我手动填写过验证码，为什么“重新尝试”仍不自动覆盖

这是保留手动输入的设计。若要交回自动识别，先清空你手动填写的验证码，再点击“重新尝试”。也可以继续手动登录。

### 9. 能离线使用吗，为什么安装包有约 20 MB

验证码图片处理不依赖在线识别服务，但获取学校页面、获取新的验证码和实际登录仍然需要网络。

安装包包含本地识别引擎、模型和运行资源，因此比只含少量脚本的扩展大。运行时不需要再从外部识别服务下载模型，也不需要配置 API 密钥。

### 10. 不知道哪里出了问题，如何反馈

可以提供扩展版本、Edge 版本、当时的状态提示、是否从业务平台跳转进入，以及简短的复现步骤。扩展管理页如果有“错误”入口，也可以查看其内容。

## 升级、停用与卸载

### 已经加载了本项目的 dist 目录

1. 确认该目录中的文件已经更新为新版本；开发者修改源码后，需要先重新构建。
2. 在 `edge://extensions` 找到扩展，点击“重新加载”。
3. 确认版本号正确，必要时按浏览器提示重新启用。
4. 刷新学校登录页。

### 使用解压后的安装包目录

完整解压新版安装包，停用或移除旧版本，再按安装步骤加载新目录。不要同时启用两份。

从 0.1.0 升级会新增 `debugger` 权限；从 0.1.1 或 0.1.2 升级到 0.1.3，不新增权限。

### 临时停用与移除

临时不使用时，关闭扩展面板中的“自动填写并登录”，或在 Edge 扩展管理页禁用整个扩展。

不再需要时，在 `edge://extensions` 点击本扩展的“移除”。移除之后再删除它的解压目录。移除本扩展不会删除 Edge 密码管理器中由你保存的账号。

## 隐私、联网与浏览器权限

### 账号密码由谁处理

扩展检查登录页上的账号密码字段是否已有值、输入是否稳定，**不读取 Edge 的密码库，不在扩展中保存、记录或向外部识别服务发送学号密码**。

实际登录时，账号密码仍由学校网页原有的登录逻辑提交给学校认证系统。本扩展只是调用网页原有的登录按钮，不接管学校的身份验证服务。

### 验证码在哪里识别

验证码使用随扩展打包的 Tesseract.js 引擎及模型，在本机处理。图片仅在内存中用于识别，不上传外部 OCR 服务；扩展没有遥测或分析上传功能。

为了保证识别结果对应当前会话，扩展会向认证页自身的 `/cas/code` 接口获取新验证码，并让页面显示这份响应中的同一张图片。你看到验证码更新属于正常现象。

“本地识别”并不表示整个登录过程不联网。学校网页自身加载的资源、访问学校验证码接口和学校的登录请求仍然属于正常联网过程。

### 为什么需要这些权限

| 权限 | 当前实现中的用途 |
| --- | --- |
| `storage` | 保存启用开关；在扩展会话中保留尝试计数、状态、文档／任务标识，避免页面刷新后无限重试 |
| `offscreen` | 在不可见的扩展内部页面运行本地识别引擎，不为每次识别新开一个窗口 |
| `debugger` | 账号密码仅显示为预填充、实际值尚未就绪时，在当前前台认证页发送一次验证码框点击 |

`debugger` 本身是范围较大的浏览器权限，不能理解成浏览器只授予了“一次点击”的能力。**本项目代码**将实际用途限制在上述激活动作，只发送鼠标按下和释放命令，没有通用调试命令入口。

页面脚本匹配范围是 `https://pass.hust.edu.cn/cas/login*`，运行时还会校验路径必须精确为 `/cas/login`。不申请 Cookie 或历史记录权限。

第三方软件许可证汇总在已构建目录中的 `THIRD_PARTY_NOTICES.txt`。

## 开发与源码说明

普通用户可以跳过本节。已构建安装包只需要 Edge；以下工具用于修改、测试和重新打包源码。

### 环境与首次构建

需要 Node.js 24 或更新版本，以及 Microsoft Edge。首次安装依赖需要联网。Git 用于查看历史和保存修改。

在项目根目录——也就是包含 `package.json` 的文件夹——打开终端，执行：

```powershell
npm ci
npm run build
```

构建成功后会生成 `dist`。在 Edge 中加载该目录，之后每次修改源码都需要重新构建、重新加载扩展，再刷新被测试的登录页。

源码仓库忽略 `node_modules`、`dist`、`release` 等生成目录。仅获取源码不意味着已经拿到了安装包。

### 常用命令

| 命令 | 用途 |
| --- | --- |
| `npm ci` | 按锁文件安装开发依赖 |
| `npm run build` | 构建扩展，并复制本地 OCR 引擎、WASM 和模型到 `dist` |
| `npm run typecheck` | 检查 TypeScript 类型 |
| `npm test` | 执行单元测试；后台相关测试读取最新构建的代码，因此修改后台后先构建 |
| `npm run test:autofill` | 在独立 Edge 配置中检查自动填充与激活场景 |
| `npm run test:browser` | 在独立 Edge 配置中检查登录流程与错误处理 |
| `npm run evaluate -- dev` | 评估 40 张开发样本 |
| `npm run evaluate -- validation` | 评估 100 张独立验收样本 |
| `node scripts/live-smoke.mjs` | 只读检查实际学校登录页，阻断全部 POST，不提交真实登录 |
| `npm run package` | 将当前 `dist` 打成 ZIP，附带 README 和 SHA256 校验文件，并逐文件检查 ZIP 内容 |

打包前先构建，避免将旧脚本打进新包：

```powershell
npm run build
npm run typecheck
npm test
npm run test:autofill
npm run test:browser
npm run package
```

输出文件位于 `release/`，例如 `hust-pass-assistant-v0.1.3.zip` 和同名的 `.sha256` 文件。重新打包会更新该版本的 ZIP；运行识别功能不需要这个打包工具。

### 目录与实现概览

```text
项目根目录/
├── src/                   扩展逻辑、页面交互与本地识别代码
├── public/                manifest、弹窗和其他静态文件
├── scripts/               构建、打包、样本评估和浏览器测试脚本
├── tests/                 单元测试与验证码样本
├── docs/                  验证说明和已保存的结果
├── dist/                  生成的可加载扩展，忽略于 Git
├── release/               生成的安装包，忽略于 Git
├── test-results/          本次运行产生的临时测试报告，忽略于 Git
└── .cache/                临时浏览器配置和缓存，忽略于 Git
```

扩展使用 Manifest V3、TypeScript 和 esbuild。内容脚本负责认证页交互；后台负责任务协调、尝试计数和自动填充激活；隐藏的扩展页面运行本地 OCR。GIF 由 `gifuct-js` 解码，再通过多帧融合、去噪和多种预处理结果的一致性判断识别数字。OCR 指光学字符识别，即从图片中读出文字或数字。

浏览器测试会创建独立临时配置，不使用日常浏览器中的账号。模拟测试把请求拦截到本地测试内容，不会向学校提交假测试密码。

只有重新采集样本或生成 GIF 参考数据时，才需要 Python 和 Pillow。`python scripts/collect-samples.py` 会访问公开验证码接口；已有样本及人工标注随源码提供，正常安装和使用扩展不需要执行它。

版本由 Git 管理，代码发布标签为 `v0.1.3`。源码、依赖锁文件及必要测试数据受版本控制；构建产物和临时浏览器会话不提交。第三方依赖版本以 `package-lock.json` 为准。
